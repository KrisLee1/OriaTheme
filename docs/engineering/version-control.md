# 版本控制规则

## 权威范围

- Git 保存精确文件历史和普通 Fast/Review 任务历史；状态、日志和 ADR 不复制逐文件时间线。
- `main` 是 Changesets 基线和发布工作流入口。普通任务不得假设有权提交、推送、发布或改写历史。
- 开始修改前检查工作树，保留用户已有修改；只处理当前任务范围内的冲突。

## 安全边界

- 未经明确授权，不添加/修改 remote，不 push，不 publish，不创建或合并 PR，不重写历史。
- 不使用 `git reset --hard`、强制 checkout 或等价方式丢弃修改；需要删除生成物时先精确确认目标和可恢复性。
- 不提交 `.gitignore` 已排除的依赖、构建产物、框架缓存、测试报告、环境文件、日志或本地 tarball。
- `pnpm-lock.yaml` 是唯一 workspace lockfile；其他包管理器的验证只在隔离消费者项目执行。

## 变更与发布记录

- 公开包行为改变时按 semver 添加 Changeset；文档、私有应用或内部流程变化不自动要求 Changeset。
- 持久架构、兼容性、协议/持久化、主要依赖、安全或发布决策使用 ADR；普通实现判断由 Git 保存。
- 发布步骤与门禁以[构建与发布](packaging.md)为准；本地验证不得被描述为已发布或已部署。

## 交付检查

- 使用 `git status --short` 识别任务内与既有修改。
- 使用 `git diff --check` 检查已跟踪改动的空白错误，并以 `git diff` 核对实际范围。
- ignored 的内部蓝图文档不出现在普通 `git diff` 中，仍须通过链接/内容校验和显式文件清单交付。
